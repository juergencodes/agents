# Structuring a Shared Project State

The shared project state is a compact handoff document for a human and an AI. Organize it so a reader can quickly determine what the project is, what is currently true, and what remains to be decided or done.

Adapt the structure to the project. Include only sections that provide ongoing value. A useful starting structure is:

1. **Project and goal** — brief context and intended outcome.
2. **Current status** — where the work stands now.
3. **Decisions** — confirmed choices that constrain future work, with brief rationale when useful.
4. **Assumptions and open questions** — clearly distinguish provisional assumptions from unresolved decisions.
5. **Next steps** — only actionable, still-relevant work.
6. **Key references** — links or paths to authoritative artifacts.

Prefer short headings, concise bullets, and direct language. Avoid duplicating details already maintained in authoritative project artifacts; link to those instead. Do not prescribe a fixed template when the project is simple enough to need less structure.

The document should be understandable without access to hidden model context. Use explicit names and enough context to make important decisions intelligible, while keeping details proportionate to their future relevance.
