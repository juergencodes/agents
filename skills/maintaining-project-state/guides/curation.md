# Curating and Updating Project State

The shared state represents the current, relevant project knowledge. It is not a transcript, task ledger, or archive.

## Add or update information when

- A decision is confirmed and will affect future work.
- The project goal, constraints, status, or authoritative references change.
- A previously recorded assumption is confirmed, rejected, or materially revised.
- An open question is resolved or a new important question emerges.
- The next steps change enough that the existing list would mislead a future continuation.

## Usually omit or remove

- Routine conversation details and chronological narration.
- Completed steps that do not establish lasting knowledge.
- Superseded decisions, stale plans, and redundant explanations.
- Tentative ideas presented as though they were agreed.
- Detailed intermediate notes that belong in a working document or workspace instead.

## Apply updates carefully

1. Inspect the current state and relevant source artifacts before editing.
2. Preserve confirmed information that remains valid.
3. Make the smallest changes that keep the document accurate and useful.
4. Consolidate duplicated or stale material; do not simply append every update.
5. Keep facts, decisions, assumptions, and open questions distinguishable.
6. After editing, check that the document remains readable, concise, and internally consistent.
7. Briefly summarize the update to the user.

If a proposed update conflicts with the current state or authoritative artifacts, do not silently choose one. Explain the conflict and ask for clarification when it cannot be resolved from the task context.

Never report a successful update unless the write actually succeeded. If access or write capability is missing, provide the proposed change as a proposal and state that the file was not updated.
